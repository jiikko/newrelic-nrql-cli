# 004 bug: リージョンを間違えると、エラーではなく 0 件が返る

## 症状（実測 2026-09-15）

US リージョンのアカウント ID に対して `-region eu` を付けて実行すると、
認証エラーにも GraphQL エラーにもならず、**`count 0` が返る**。

```console
$ nrql -a <US のアカウント> -region eu "SELECT count(*) FROM Transaction SINCE 10 minutes ago"
count
0
$ nrql -a <US のアカウント> "SELECT count(*) FROM Transaction SINCE 10 minutes ago"
count
198176
```

US のセッション Cookie は `.newrelic.com` のドメイン Cookie なので `one.eu.newrelic.com`
にも送られ、EU 側のホストがリクエストを受理してしまうのが原因と考えられる（未確定）。

## なぜ問題か

「データが無い」と「リージョン設定が誤っている」を利用者が区別できない。
`0` を信じて「異常なし」と判断する形の誤りを作る。

## 検討した対策

- **`actor.accounts` にそのアカウント ID が含まれるか確認する** — 1 往復増える。
  0 件のときだけ確認すれば常時コストはかからない（有力）
- レスポンスの `data.actor.account` が null かどうかで判定する — 今回の実測では
  null ではなく結果が返っているので、**この判定は効かない可能性がある**（要確認）
- 何もせず README で警告する — 現状これだけ実施済み

## 受け入れ条件

- [ ] リージョン誤りを検出できる条件を実測で確定する（0 件のときのレスポンス全体を観測）
- [ ] 検出できるなら、0 件時に警告を出す（誤検出で正当な 0 件を汚さないこと）
- [ ] 検出できないなら、その結論と根拠をこの issue と README に書いて閉じる


---

## 決着（2026-09-15、v0.1.3）

**原因はリージョン固有ではなかった。** `nrqlResponse` が値型のネスト struct だったため、
NerdGraph が `account: null` を返しても `json.Decode` はエラーを出さずゼロ値を作り、
`len(rows)==0` に落ちて「0 件」rc=0 で終わっていた。リージョン違いはその 1 入口に過ぎず、
**アカウント ID のタイポ・権限不足でも同じ症状**になっていた。

対応: 各階層をポインタにして「引けなかった」と「0 件だった」を型で分けた
（`cmd/nrql/nrql.go`）。アカウントを参照できない場合は、ID の誤り・権限不足・
リージョン違いの 3 つを候補として挙げるエラーを返す。

検証:
- httptest で `account:null` / `actor:null` / `nrql:null` / 本物の 0 件 / 1 件 を区別できることを固定
- 変異検証: ポインタを値型へ戻すと該当 3 ケースが red
- 実環境: 存在しないアカウント ID で rc=1（NerdGraph が `Access denied.` を返す）

残っていた「検出方法の検討」は不要になったのでこの issue は閉じる。
`actor.accounts` との突合という案も、型で分けられたため採らない。
