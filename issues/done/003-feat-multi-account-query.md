# 003 feat: 複数アカウントの同時クエリ（`-a a,b,c`）

## 背景

NRQL の `WHERE` ではアカウントを跨げない（issue 001 の「分かったこと」参照）。
一方 NerdGraph には複数アカウントを 1 クエリで読む形式があり、**実験で通ることを確認した**。

```graphql
# 現在の実装（単一）
{ actor { account(id: A) { nrql(query: "...") { results } } } }

# 複数形式（実験で 200 が返り、合算値が得られた）
{ actor { nrql(accounts: [A, B], query: "...") { results } } }
```

用途は「全環境（本番・ステージング）のエラー率をまとめて見る」など。

## 設計メモ

- `-a` / `-account` をカンマ区切り（`-a 123,456`）で受ける
- **単一指定時の挙動を変えない**のが条件。`accounts: [A]` に一本化してよいかは未検証なので、
  1 件のときは今の `account(id:)` 形式を使い、2 件以上のときだけ複数形式へ切り替える
  （検証済みの形を壊さない）
- `config.yml` の `account` も複数指定を受けるか要検討（受けるなら形式の互換に注意）

## 未解決

- **`FACET accountId` でアカウント別に割れなかった**（実験で結果 0 件）。合算しか取れないなら
  用途が限られるため、**まず「アカウント別に割る方法があるか」を調べる**のが先。
  無いなら、CLI 側でアカウントごとに逐次クエリして結果を結合する方が有用かもしれない
  （その場合 NerdGraph の複数形式は使わない）

## 受け入れ条件

- [ ] `-a A,B` で 2 アカウントの結果が返る
- [ ] `-a A`（単一）の出力が現在と 1 バイトも変わらない
- [ ] アカウント別に割る方法の結論（割れる / 割れないので逐次クエリにする / 見送り）を本文に書く

## 決着（2026-09-16、v0.1.5）

### 実装

`-a 1234567,2345678` のようにカンマ区切りで複数指定できるようにした。

- **1 件のときは従来の `account(id:)` の形を使い続ける**（実測で通ることを確認したのはこちら。
  `accounts: [A]` に一本化してよいかは未検証なので、検証済みの形を壊さない）
- 2 件以上のときだけ `actor { nrql(accounts: [...]) }` へ切り替える
- 重複は畳み、指定順を保つ。0 / 負数 / 数値でない値は使い方エラー（rc=2）

### 合算されることの実測（2026-09-16）

移動窓（`SINCE 30 minutes ago`）だと件数がドリフトして比較にならなかったので、
固定窓（`SINCE 3 hours ago UNTIL 2 hours ago`）で 3 回測った。

| 試行 | A 単独 | B 単独 | A+B（期待） | 同時指定 |
|---|---|---|---|---|
| 1 | 1,214,553 | 1,126 | 1,215,679 | 1,215,695 |
| 2 | 1,214,559 | 1,123 | 1,215,682 | 1,215,668 |
| 3 | 1,214,516 | 1,125 | 1,215,641 | 1,215,505 |

差は数十件で、これは測定のあいだにもデータが増えているため。**合算されている**。
3 アカウントの同時指定も通る。

### アカウント別に割る方法（未解決だった点の答え）

**`FACET tags.accountId` で割れる**（実測）。

```
$ nrql -a A,B -format table "SELECT count(*) FROM Transaction FACET tags.accountId SINCE ..."
facet    count      tags.accountId
-----    -----      --------------
1234567  1,213,626  1234567
2345678  1,124      2345678
```

- `FACET accountId` は **0 件**（イベントの属性ではないため。issues/done/004 と同じ理由）
- `FACET account` は別物（アプリ側の属性で、New Relic のアカウント ID ではない）

### 権限の扱い

指定したうちの 1 つでも権限が無いと、**クエリ全体が失敗**する
（`NerdGraph エラー: You do not have access to one or more of the accounts you provided.`）。
部分的な結果は返らない。案内文にもその旨を書いた。
