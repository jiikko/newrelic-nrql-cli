# 003 feat: 複数アカウントの同時クエリ（`-a a,b,c`）

## 背景

NRQL の `WHERE` ではアカウントを跨げない（issue 001 の「分かったこと」参照）。
一方 NerdGraph には複数アカウントを 1 クエリで読む形式があり、**実験で通ることを確認した**。

```graphql
# 現在の実装（単一）
{ actor { account(id: A) { nrql(query: "...") { results } } } }

# 複数形式（実験で 200 が返り、合算値が得られた）
{ actor { nrql(accounts: [A, B], query: "...") { results } } }
```

用途は「全環境（本番・ステージング）のエラー率をまとめて見る」など。

## 設計メモ

- `-a` / `-account` をカンマ区切り（`-a 123,456`）で受ける
- **単一指定時の挙動を変えない**のが条件。`accounts: [A]` に一本化してよいかは未検証なので、
  1 件のときは今の `account(id:)` 形式を使い、2 件以上のときだけ複数形式へ切り替える
  （検証済みの形を壊さない）
- `config.yml` の `account` も複数指定を受けるか要検討（受けるなら形式の互換に注意）

## 未解決

- **`FACET accountId` でアカウント別に割れなかった**（実験で結果 0 件）。合算しか取れないなら
  用途が限られるため、**まず「アカウント別に割る方法があるか」を調べる**のが先。
  無いなら、CLI 側でアカウントごとに逐次クエリして結果を結合する方が有用かもしれない
  （その場合 NerdGraph の複数形式は使わない）

- [ ] `-a A`（単一）の出力が現在と 1 バイトも変わらない
- [ ] アカウント別に割る方法の結論（割れる / 割れないので逐次クエリにする / 見送り）を本文に書く
